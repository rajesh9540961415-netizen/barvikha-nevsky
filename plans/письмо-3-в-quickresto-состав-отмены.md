Здравствуйте!

Это третий вопрос по Back Office API, не связанный с предыдущими двумя (`front.orders` и «Персонал → Должности»).

Доступ настроен и работает: базовый адрес `https://fk381.quickresto.ru/platform/online`, авторизация Basic, отдельные логин и пароль для API. Облако: **fk381**.

### Что видно в бэк-офисе

В разделе «Отмены» открываем карточку любой отмены — и в ней **видно отменённое блюдо**. То есть данные в системе есть.

### Чего нет в API

`front.cancellations` возвращает по каждой отмене ровно 20 полей:

```
id, version, serverRegisterTime, localCreateTime, localTimeZoneOffsetMin,
createTerminalSalePlaceDocId, createTerminalSalePlace,
tableSchemeDocId, tableScheme,
cancellationReasonDocId, cancellationReason,
userDocId, employee, tableOrderDocId,
comment, description, withDismission, cloudId, _id, className
```

**Поля с составом среди них нет.** Ни названия позиции, ни количества, ни цены.

Проверили не по одной записи: просмотрели **200 отмен подряд** и собрали объединение всех ключей — состав не встречается ни у одной.

### Карточку по отдельному запросу получить удалось, но она та же самая

Сначала `/api/get` отвечал HTTP 400 с подсказкой:

```json
{"errorCode":"formatError",
 "errorDescription":"Either objectId or objectRid should be specified"}
```

Подставили `objectId` — карточка пришла:

```
/api/get?moduleName=front.cancellations&objectId=160590
```

**Вернулись те же 20 полей.** То есть это не вопрос неправильного вызова: по этому модулю состава нет ни в списке, ни в карточке.

### Пробовали дойти до состава через заказ

В отмене есть ссылка на заказ:

```
tableOrderDocId: "table_order-240429074706063E|00000584=2608301750237570"
```

Запрос `/api/get?objectRid=<этот идентификатор>` во всех доступных нам модулях отвечает:

```json
{"errorCode":"entityNotFound","errorDescription":"Entity with objectRid = 'table_order-...'"}
```

Сам `front.orders` состава тоже не отдаёт. Просмотрели **200 заказов подряд**, объединение ключей — 51 поле: стол, официант, кассир, номер документа, все суммы, платежи. **Позиций нет ни у одного заказа.**

### Какие названия модулей пробовали

HTTP 400 («модуль не найден») отвечают все:

```
front.tableorder     front.tableorders    front.orders.tableorder
front.tables         front.precheck       front.prechecks
front.discards       front.orderitem      front.orderitems
front.orders.items   front.sales          front.shifts
front.menu           front.checks         front.receipts
menu.menu            menu.dishes          menu.products
reports.sales        warehouse.writeoffs  warehouse.documents
```

Служебных страниц со списком модулей тоже нет: `/api/modules`, `/api/meta`, `/api/describe`, `/api/schema` — HTTP 404.

### Вопросы

1. Каким `moduleName` можно получить **состав отменённой позиции** — что именно отменили, в каком количестве и по какой цене?
2. Каким `moduleName` можно получить **состав заказа** (позиции чека до фискализации)?
3. Есть ли модуль для **заказов по столам** — документов с идентификатором вида `table_order-…`? В доступных нам модулях они не находятся.
4. Если состав отдаётся только при дополнительных правах ключа — подскажите, какие права запросить и на кого оформить заявку.
5. Если в открытом API состава нет вовсе — подтвердите, пожалуйста, прямо. Тогда мы перейдём на ручную выгрузку отчёта и перестанем искать.

### Зачем нам это

Проверяем сохранность выручки. Нужно понимать, что происходит с отменённой позицией: если официант ошибочно пробил блюдо на один стол, отменил и перебил на другой — это рабочая ситуация, и она должна быть видна как перенос. Если же отменённое блюдо нигде больше не появляется, это уже вопрос к смене.

Составы фискальных чеков у нас есть — они приходят по API оператора фискальных данных. Не хватает ровно одного звена: **что именно было отменено**. С ним проверка закрывается полностью и автоматически, без ручной работы администратора.
