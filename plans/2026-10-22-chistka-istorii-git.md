# Чистка истории git от персональных данных

**Решение владельца 22.10.2026:** персональные данные — вон из гита (решение
25.08 «всё равно переноси» отменено). Текущие файлы выведены из-под гита
коммитом `a3a84b0`, но в истории они остались: на GitHub, в git Amvera
и в `.git` на VPS. Способ чистки GitHub выбрала владелец: **удалить
репозиторий и завести новый, чистый** — надёжнее, чем перезапись с запросом
в поддержку GitHub.

Что вычищаем — `scripts/git-chistka/puti.txt` (формат `git filter-repo
--paths-from-file`): папка «Резервные копии», фото листов смен (README
остаётся), документы ОВМ, рабочие json с именами, снимки облака, замок
LibreOffice и свод вознаграждений в корне (в текущих файлах его нет с
13.08, а в истории есть).

**Приложение от GitHub не зависит:** Amvera собирает из своего git
(`amvera/master` = `main` на VPS, GitHub-`main` старше). Удаление
репозитория на GitHub работу смены не трогает.

## Фазы

### [x] Фаза 0. Подготовка — 22.10.2026
- `git-filter-repo` v2.47.0 поставлен в `~/.local/bin` (pip и sudo на VPS
  нет; это один файл на Python, sha256 `67447413…7d94`).
- Репетиция на одноразовой копии: 542 коммита, история 47 → 6,4 МБ,
  из чувствительного осталось только `data/листы-смен/README.md`. Дерево
  `work` после чистки байт в байт как сейчас. Копия удалена.
- Ссылки на документы ОВМ отданы владельцу — после чистки других копий
  не будет (кроме git Amvera до её перезаписи).

### [ ] Фаза 1. Утро, окно 7:00–11:00 — чистка на VPS
1. Убедиться, что владелец сохранила документы ОВМ.
2. `git status` чистый, ветка `work`.
3. Запомнить, куда смотрят ремоуты: `git remote -v` (filter-repo удаляет
   `origin`, остальные — нет, но лучше сверить).
4. `PATH=$HOME/.local/bin:$PATH git filter-repo --force --invert-paths
   --paths-from-file scripts/git-chistka/puti.txt`
5. Проверка: `git log --all --name-only` — из списка ничего, кроме README;
   файлы на диске (листы, «Резервные копии») на месте — filter-repo
   рабочие файлы вне гита не трогает, но сверить.
6. Вернуть `origin` (если удалён) на новый адрес — после фазы 2.

### [ ] Фаза 2. Владелец — GitHub
1. Старый репозиторий: Settings → внизу **Delete this repository**.
2. Новый: приватный, то же имя, **пустой** (без README и .gitignore).
3. Settings → Deploy keys → Add deploy key: открытая часть
   `~/.ssh/id_ed25519_github_deploy.pub`, галочка **Allow write access**.

### [ ] Фаза 3. Отправка в новый репозиторий
- `git push origin work` — только `work`, по разрешению владельца.
- Сверить `git ls-remote origin` с `work`.

### [ ] Фаза 4. Amvera — при следующей выкладке
В `amvera/master` старая история. После чистки `main` на VPS с ней
не сходится, поэтому следующая выкладка приложения смены — **только
принудительно** и **только в окно 7:00–11:00**, с разрешения владельца:
`git push --force amvera main:master`. Бэк-офис (`amvera-manager`)
и робот (`amvera-reader`) уезжают subtree-веткой одной папки — в их
истории файлов из списка нет, проверить `git ls-tree` перед выкладкой.
