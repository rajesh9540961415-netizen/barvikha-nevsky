### Что есть в бэк-офисе

В разделе «Персонал» у нас есть подразделы: **Сотрудники, Должности, График работы, Шаблон смен, История действий**.

У каждого сотрудника проставлена должность — «Официант», «Кассир», «Администратор зала (Менеджер)», «Суперпользователь бэк-офиса», — и список сотрудников группируется по должностям. В карточке сотрудника есть вкладки «Оплата труда», «Выписка по оплате труда», «Выписка по отработанным часам».

### Чего нет в API

Запрос к `personnel.employee` возвращает по каждому сотруднику только эти поля:

```
className, cloudId, id, version, user, systemEmployee, blocked,
firstName, middleName, lastName, fullName, shortName,
dateOfBirth, allowedTablesSchemes
```

**Должности среди них нет.** ПИН-кода доступа на терминал тоже нет.

Наглядный пример. Мы завели сотрудника в двух должностях — «Администратор зала (Менеджер)» и «Кассир». В бэк-офисе это две карточки с разными ПИН-кодами (1111 и 1977). Через API обе карточки приходят с одинаковым `fullName` и **без единого поля, по которому их можно различить**:

```json
{ "id": 913, "fullName": "Ивана Ивановна Иванова", "shortName": "Иванова И.", ... }
{ "id": 914, "fullName": "Ивана Ивановна Иванова", "shortName": "Иванова И.", ... }
```

### Что пробовали, чтобы получить карточку целиком

| Запрос | Ответ |
|---|---|
| `/api/get?moduleName=personnel.employee&id=913` | HTTP 400 |
| `/api/object`, `/api/detail` | HTTP 404 |
| `/api/list` с фильтром по `id` | те же поля |
| параметры `full=true`, `expand=all`, `fields=...` | игнорируются, те же поля |

### Какие разделы вообще отвечают

Перебрали названия модулей. HTTP 200 возвращают только восемь:

```
personnel.employee      front.orders            front.preorders
front.zreport           front.tablemanagement   front.terminals
core.company            warehouse.nomenclature
```

Всё, что пробовали для персонала, отвечает HTTP 400: `personnel.position`, `personnel.positions`, `personnel.role`, `personnel.roles`, `personnel.job`, `personnel.jobtitle`, `personnel.workshift`, `personnel.workshifts`, `personnel.timesheet`, `personnel.schedule`, `personnel.staff`, `personnel.department`, `personnel.attendance`.

Побочное наблюдение: параметр `className`, судя по всему, не влияет на результат — запрос с заведомо неверным `className` при верном `moduleName` возвращает те же данные. Если это так, подскажите, нужен ли он вообще.
