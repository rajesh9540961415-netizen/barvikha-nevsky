### [ ] Фаза 6. Сверка с Рестоплейс — через API

Два самых денежных пункта чек-листа непроверяемы без данных из системы бронирования:
- **бронь реально заведена** — сейчас знаем только, что хостес *сказала* «забронировала»

**У Рестоплейс есть открытый API** (проверено 04.08.2026 по их документации `restoplace.cc/help/API`). Руками ходить не нужно, делаем как с Quick Resto.

| Ключ | заголовок `X-API-Key` или параметр `?api_key=` |

Статусы: 1 новая, 2 заявка, 3 ожидаем, 4 открыт, 5 закрыт, 6 отменён, **8 отменён из-за неоплаченного депозита**.

### 🚩 Статус 8 — красный флаг, а не разновидность отмены

**На Невском депозитов сейчас нет.** *Собственник, 07.08.2026.* Значит бронь, слетевшая из-за неоплаченного депозита, **не должна появляться вообще**.

Появилась — это не работа хостес и не поведение гостя, а **сбой в настройках Рестоплейс**: гостю выставили требование оплатить то, чего заведение не берёт. Он не оплатил, бронь тихо слетела. Заведение об этом не узнало.

Поэтому в разборе статус 8 идёт **не в отмены**, а отдельной строкой с пометкой, и попадает в отчёт даже в единственном экземпляре — здесь важен сам факт, а не частота.

То же самое по полю **`depositPaid`**: на любой броне Невского оно должно быть пустым или отрицательным. Заполнено — тот же флаг, даже если бронь при этом жива.

⚠️ Проверить это можно **только после подключения API** — из звонков не видно ничего. Первым же запросом `GET /reserves` стоит посмотреть, есть ли восьмёрки в прошлом: если да, деньги теряются прямо сейчас и неизвестно, как давно.

**Как сводить звонок с бронью.** Ключ сопоставления — **телефон гостя**: в выгрузке Zoon это `phone_from`, в Рестоплейс — `phone`. Плюс окно по времени: бронь создана в пределах часа после звонка.

Что это даёт по чек-листу:

| Пункт | Как проверяется |
|---|---|
| Бронь заведена в системе | телефон из звонка нашёлся в бронях за тот же день |
| **+30 минут** | `time_to − time_from` должно равняться **озвученному в разговоре + 30 мин**. Штатная бронь обычного стола: в звонке 3 часа → в брони 3,5. Ровно 3 часа в системе — правило не применили; 3 часа в системе при озвученных 2,5 — хостес назвала гостю внутреннюю цифру. Исключение — мероприятия |
| Количество гостей | `count` против названного в звонке |
| Размещение | `item_ids` / `floor_id` против обещанного стола |

**Несовпадения — тоже находка,** а не сбой сопоставления: бронь на другой номер, на другое время, на другое количество гостей. Каждый такой случай стоит разбирать отдельно.

Альтернатива ключу — **вебхук**: Рестоплейс сам шлёт события по броням. Пригодится, когда дойдём до автоматики, но для разбора задним числом проще `GET /reserves`.

Что нужно от владельца: подтвердить тариф ПРО+, включить API и положить ключ в `.env` как `RP_API_KEY`.

## Что решено — не переспрашивать

| Вопрос | Ответ |
|---|---|
| Кто принимает звонки | **Хостес** в зале, не операторы. Женский род |
| Список хостес со сменами | Не существует. Имя берём из приветствия, список выращиваем из частот. Приём сработал: 7 имён настоящих, мусор осел в хвосте |
| VIP на Невском | 6 комнат, **2000 ₽/час для всех**, от размера не зависит. До 18:00 почасово, с 18:00 минимум 2 часа |
| Цены других заведений | Хостес **не называет**. Общее — отвечает сама, на конкретику предлагает варианты: взять контакт гостя для обратного звонка либо направить на Яндекс / сайт сети. «Не знаю» без решения — ошибка |
| Дети | Вход 18+. Ребёнок — только с родителем и **двумя документами**: свидетельство о рождении ребёнка + паспорт родителя, сверяют фамилию. *07.08: это **наше правило точки**, постоянное. В файл сети его дописывать не просим, с сетью вопрос решается отдельно. Хостес обязаны называть оба документа — неполный ответ считается ошибкой* |
| **Депозиты** *(07.08)* | **На Невском их сейчас нет.** В сетевом xlsx депозитная система под праздники описана — у нас не применяется. Следствия: хостес на неё не ссылается; статус 8 в Рестоплейс становится 🚩 красным флагом (см. фазу 6); «больше 3 часов» решается наличием следующей брони, а не депозитом |
| **Тип места в разборе** *(07.08)* | Фиксируем обязательно: **обычный стол / VIP / бар**. Без этого две нормы продолжительности — потолок у стола и минимум у VIP — не разделить. Отдельная колонка `тип_места` в `analysis-*.csv`, вводится со следующей выгрузкой |
| **Продолжительность** *(07.08)* | Обычный стол — **бронь на 3 часа, это потолок, о нём предупреждают.** VIP — **минимум 2 часа с 18:00, верхнего предела нет** (ограничивает только следующая бронь на комнату). Что дальше, когда гость просит больше, **в контроль не берём** |
| **Расхождение с документом сети** *(07.08)* | В xlsx сети написано «начинаем с 2 часов» — с нормой точки не сходится. **Вопрос закрыт: собственник урегулирует с сетью сам.** Контроль качества считает по норме точки, к этому не возвращаемся |
| **+30 минут** *(07.08)* | Правило сети **действует**. К озвученному гостю времени в системе добавляется полчаса: штатная бронь обычного стола — гость слышит **3 часа**, в Рестоплейс стоит **3,5**. Подтверждено собственником. Полчаса — внутренняя цифра, гостю не называется |
| Вопрос «откуда узнали» | Обязательный шаг. Ответ храним, **статистику не строим** |
| Локальные шаги | «Ранее бывали», «номер как контактный», уточнение зала — стандарты, в контроле |
