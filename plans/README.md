# Планы

Технические планы реализации. Здесь живёт информация **как** мы делаем проект (в отличие от `.business/`, где живёт **зачем**).

## Правила

1. **Один план = одна функция.** Если план на эту функцию уже есть — работаем с ним, новый не заводим.
2. **Имя файла:** `YYYY-MM-DD-название-функции.md`.
3. **План делится на фазы.** У каждой фазы статус `[ ]` (не сделано) или `[x]` (сделано).
4. **В конце плана — итоговый блок:** реализовано целиком или нет, что осталось.
5. **Актуализация после каждой сессии.** План должен отражать реальное состояние, а не первоначальный замысел.
