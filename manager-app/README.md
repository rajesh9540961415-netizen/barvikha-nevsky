# Бэк-офис

> **Выложен 13.08.2026** — приложение `nevsky-office` в Amvera, регион Москва,
> тариф «Начальный». Выкладка: `git subtree push --prefix manager-app amvera-manager master`,
> безопасна в любое время — приложение смены она не трогает.
>
> ⚠️ **Имя намеренно не про чаевые.** По плану архитектуры
> (`../plans/2026-08-11-arhitektura.md`) сюда переедут ещё финансы и звонки —
> разделами, а не отдельными приложениями. Иначе вернёмся к тому, от чего ушли:
> приложение под каждую задачу, в каждом свой вход, свои роли, своя выкладка.
>
> ⚠️ **Регион Москва обязателен.** Ему нужна база, а внутреннее имя базы
> разрешается только внутри своего региона — проверено на роботе 13.08.2026.

Смена вносит деньги в приложении смены, читатель QR-чаевых живёт отдельно, здесь управляющий состав смотрит и исправляет.

**База общая** с приложением смены — та же PostgreSQL на Amvera. Никаких копий и выгрузок между приложениями: у двух копий одних и тех же денег рано или поздно расходятся суммы, и выяснить, какая права, уже нельзя.

## Что уже умеет

| Экран | Что там |
|---|---|
| `/` — список смен | суммы по видам денег, метка «правлено» |
| `/shift/ГГГГ-ММ-ДД` | раскладка смены, состав, все записи, правка и отмена |
| `/people` | один сотрудник: смены за период, динамика, итоги |

**Бэк-офис показывает начисления, а не выплату.** Решение владельца 07.08.2026. Сколько человеку причитается — считается здесь; сколько ему выдали на руки за вычетом съеденного — дело смены, она деньги и раздаёт. Поэтому питания на экранах нет, а колонка называется **«начислено»**: заработок минус доли администратору и кассиру.

⚠️ **Из расчёта питание при этом не убрано** — убрать значило бы показывать в двух приложениях разные деньги одному человеку. Записи о питании в списке смены видны и правятся: больше их править негде, смена умеет отменять только последнюю запись.

**Экран сотрудника не пропускает смены.** Вечер, когда заведение работало, а человек — нет, стоит в таблице с пометкой «не в смене». Иначе десять строк подряд выглядели бы как десять смен, а на деле их могло быть три. Календарные дни без смен не показываются: день, когда заведение не работало, — не прогул.

⚠️ **Все суммы на экранах — то, что дошло, а не то, что оставил гость.** Сбер удерживает 8 % с чаевых на терминале, причём с получателя. Поэтому у колонки «терминал» стоит звёздочка, а внизу каждого экрана — сноска с настоящей суммой комиссии за показанный период. Без неё человек, заходящий раз в месяц, решит, что цифра неверная: гость на терминале видел 1 900 ₽, а в таблице стоит 1 748 ₽.

**«Против коллег»** — на сколько процентов человек собрал больше или меньше остальных официантов **в тот же вечер**. Не с его собственным средним: абсолютные суммы говорят о людности зала, а не о человеке — в слабый вторник мало собирают все. Людность одинакова для всех, кто в этот вечер работал, поэтому из сравнения она вычитается сама.

В среднее не берутся ни сам человек (иначе он наполовину сравнивался бы с собой), ни те, кто в этот вечер не собрал ничего.

**Исправления.** Правка не переписывает запись: старая помечается отменённой и остаётся видна перечёркнутой, новая встаёт рядом и ссылается на неё. Удалять не может никто — ни смена, ни управляющий, ни владелец.

Перед сохранением показывается **«было / стало» по всей смене**, а не по одной строке. Это не украшение: заработок официанта проходит через порог 1300 ₽, и правка на полсотни рублей может перевести человека через порог — тогда пересчитываются доли администратора, кассира и итог каждого. На выдуманных данных 07.08.2026 такая правка дала +50 ₽ заработка и **−397,50 ₽ на руки**.

**Поделённые чаевые правятся группой целиком.** Гость оставил чаевые за стол один раз, а в базе они лежат несколькими строками. Правишь сумму гостя или список официантов — приложение делит заново, и доли всегда сходятся с тем, что оставил гость.

⚠️ **Официант должен быть в составе смены.** Раскладка перебирает состав, а не записи: деньги, записанные на человека вне состава, в неё не попадут и пропадут молча. Поэтому такая правка не сохраняется, пока не поправлен состав.

## Копии из приложения смены

Предпросмотр обязан считать деньги ровно так же, как приложение смены. Общей папки быть не может: Amvera собирает `mini-app` и `manager-app` как два отдельных корня, и всё за их пределами до сервера не доедет.

Поэтому четыре файла — `src/lib/split.ts`, `src/lib/types.ts`, `src/data/employees.json`, `src/data/tables.json` — лежат копиями, а копию стережёт проверка. **Править их надо в `mini-app`**, потом здесь:

```bash
cd manager-app && npm run copies
```

Проверка запускается сама перед `npm run dev` и `npm run build`: если копии разошлись, приложение не поднимется и скажет, какой файл разъехался. Молча расходящиеся правила деления денег — ровно та ошибка, которая всплывает через полгода в отчёте.

## Кто заходит

Вход **по людям**, а не общим паролем. Решение владельца 04.08.2026: заходить будут трое, потом до пяти-шести.

Дело не в безопасности как таковой. Управляющий состав правит деньги — а под общим паролем правка подписывалась бы должностью, а не именем, и спросить «почему так» было бы не у кого. Это ровно то, от чего уходили, бросая бумагу.

| Роль | Что может править |
|---|---|
| `manager` — управляющий | **факты:** сумма, официант, вид денег, состав смены, отмена ошибочной записи |
| `owner` — владелец | всё то же **плюс правила:** порог 1300 ₽, доли администратора и кассира, ставка комиссии, правки в закрытом месяце |

Уволившегося **отключаем, а не удаляем**: вместе с ним ушла бы история его правок, а это денежный след.

### Завести человека

```bash
cd manager-app && npm run manager:add -- "Имя Фамилия" логин owner
```

Последний параметр — `owner` или `manager`, по умолчанию `manager`. Пароль скрипт придумывает сам и показывает **один раз**: в базе его нет, только необратимый отпечаток. В историю команд пароль не попадает.

### Посмотреть, кто заведён

```bash
cd manager-app && npm run manager:list
```

Логины, роли, кто когда последний раз заходил и кто отключён. Паролей здесь нет и быть не может.

### Забыли пароль

Восстановить нельзя: в базе лежит отпечаток, а не пароль. Единственный способ — выдать новый.

```bash
cd manager-app && npm run manager:password -- vika
```

Старый пароль сразу перестаёт работать, новый показывается один раз. Отключённого человека новый пароль не пустит — доступ снимали намеренно, и возвращать его должна отдельная осознанная команда.

⚠️ Скрипт печатает адрес базы и схему перед тем, как что-то менять. **Смотрите на них**: перепутать свою базу с боевой легко, а последствия у этих двух разные.

## Что задать в панели Amvera

Переменные окружения, этап **«Запуск»**:

| Имя | Значение |
|---|---|
| `DATABASE_URL` | та же строка, что у приложения смены — внутренний адрес базы |
| `SESSION_SECRET` | длинная случайная строка, которой подписывается вход. **Своя, не та, что на компьютере разработчика** |

`DATABASE_SCHEMA` **не задавать** — тогда бэк-офис работает с боевой схемой `public`, как и приложение смены.

Случайную строку для `SESSION_SECRET` можно получить так:

```bash
openssl rand -base64 32
```

⚠️ Переменные читаются только при старте. После правки контейнер нужно перезапустить.

## Схему в базу применяет само приложение

При каждом старте, до того как поднимется сайт, контейнер выполняет `scripts/db-setup.mjs` — он приводит базу в соответствие со схемой.

**Почему так, а не руками.** С компьютера владельца боевая база недоступна: VPN incy перехватывает соединения на порт 5432, обойти не вышло (пробовали 04.08.2026). А бэк-офис живёт в том же дата-центре, что и база, и достаёт её без сложностей.

**Почему это не опасно.** Схема написана целиком через «создать, если ещё нет»: она ничего не удаляет и не переписывает, только добавляет недостающее. Выполнять её можно сколько угодно раз — приложение смены делает то же самое командой `npm run db:setup`.

**Не удалось — контейнер не поднимется**, и причина будет видна в журнале панели. Это нарочно: бэк-офис без нужных колонок всё равно сломается, только позже и непонятнее — посреди правки денег.

⚠️ `scripts/schema.sql` — **копия** из приложения смены, как и остальные копии. Правится в `mini-app/scripts/schema.sql`, потом `npm run copies`. Две расходящиеся схемы одной базы — это катастрофа, которую замечают последней.

## Как выложить

Бэк-офис лежит подпапкой общего репозитория, а Amvera собирает из корня. Поэтому отправляем не весь репозиторий, а только эту папку — она станет корнем:

```bash
cd "/Users/user/Documents/Невский" && git subtree push --prefix manager-app amvera-manager master
```

Один раз перед этим надо завести адрес, который выдаст панель Amvera при создании приложения:

```bash
cd "/Users/user/Documents/Невский" && git remote add amvera-manager git@git.msk0.amvera.ru:borzovavv/<имя-приложения>
```

**Выкладка бэк-офиса безопасна в любое время** — приложение смены она не трогает.

## Проверить на своём компьютере

```bash
cd manager-app && npm run dev
```

Откроется на порту **3100**, чтобы не сталкиваться с приложением смены на 3000. Настройки — в `manager-app/.env.local`, там своя база на этом компьютере и тестовая схема: боевые деньги проверками не задеваются.

### Выдуманная смена для проверок

Править нечего, пока в базе пусто. Смену можно насочинять:

```bash
cd manager-app && npm run seed
```

Кладёт **10 смен за две недели** с разным составом: кто-то выходит через раз, кто-то появляется только во второй неделе. Без разного состава экран сотрудника не проверить — там главное, чтобы пропущенные смены были видны.

Две последние расписаны подробно: 5 августа (порог, поделённые чаевые, питание, отменённая запись) и 6 августа (пятница — кассиру 1000 ₽ вместо 750 ₽). Александра 5 августа заработала ровно 1 250 ₽, на полсотни ниже порога: добавьте ей 50 ₽ правкой и увидите «мёртвую зону» — заработок вырастет, а на руки станет меньше.

Запускать можно сколько угодно раз — смены переписываются заново. Скрипт **отказывается работать**, если база не на этом компьютере или схема не тестовая: одной ошибки в строке подключения должно быть мало, чтобы выдумки попали к настоящим деньгам.
