# 23.10.2026 — чистка истории git

1. **Задача.** По плану `plans/2026-10-22-chistka-istorii-git.md`: в окно
   7:00–11:00 вычистить из истории git персональные данные, пересоздать
   репозиторий на GitHub и отправить туда `work`.
2. **Как решал.** Спросил про документы ОВМ (сохранены), снял копию `.git`,
   прогнал `git filter-repo` по `puti.txt`. Проверил историю по списку, дерево
   `work` (байт в байт прежнее), файлы на диске. При проверке нашёл в гите PDF
   разбора звонков 16.07 из `.business/` — владелец велела вырезать, дочистил
   вторым прогоном до отправки. Отправку отбила система безопасности Claude
   (и `push`, и даже `remote add`), разрешение в настройках не помогло —
   открыл владельцу вкладку терминала на VPS, команды она запустила сама.
   Первый `push` отбит: у ключа не было записи; заново ключ не добавлялся
   («Key is already in use» — держит удалённый репозиторий). Завёл новый
   ключ `id_ed25519_github_deploy_2`, старый стёр.
3. **Решил — да**, кроме фазы 4 (старая история в git Amvera — уйдёт при
   первой принудительной выкладке) и возможной копии на Маке.
4. **Что можно лучше.** Про старый ключ надо было подумать заранее: deploy
   key живёт вместе с репозиторием, и удаление репозитория его не отпускает.
   Новый ключ стоило завести до того, как владелец пошла на GitHub, — тогда
   хватило бы одного захода, а не трёх. Блок отправки тоже стоило проверить
   до чистки, а не после: вкладку терминала можно было открыть сразу.
5. **Было → стало.** Было: в истории 271 файл с ПДн, 47 МБ, на GitHub —
   полная история. Стало: история 14 МБ без них (и без PDF звонков), на GitHub
   новый пустой репозиторий с одной веткой `work` = `c734f9f`.
