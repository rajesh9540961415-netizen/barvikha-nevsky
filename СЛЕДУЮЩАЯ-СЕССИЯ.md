## 🔴 Почему утренние задачи просили разрешения

Разобрано 16.08, и это главный вывод дня — он шире одной задачи.

**Задача, которую просят проверить то, чего нет в выводе команды, сочинит
команду.** Инструкция по чаевым требовала «нет ли двойников» и «заработок
за вчера». Готового ответа в выводе не было — и задача писала на ходу
маленькую программу, чтобы это добыть. Сочинённую команду **невозможно
внести в список разрешений заранее**: завтра будет другая.

| Утро | Что было |
|---|---|
| 11.08 | нормально, 4 минуты |
| 12.08 | нормально, 1 минута |
| 13.08 | **ждала 18 минут** на самодельной программе к готовому .xlsx |
| 14.08 | прогон 6 часов; правку кода `report_build.py` ей разрешили |
| 15.08 | **ждала 36 минут** на такой же программе, но другого вида |
| 16.08 | **ждала 74 минуты и не дождалась** — снял вручную |

⚠️ **Самое важное: каждое ожидание чинилось нажатием «разрешить», и каждое
нажатие расширяло права.** В списке до очистки 15.08 лежали ровно две широкие
строки, и обе выросли из этих утр:

| Строка в списке | Откуда взялась |
|---|---|
| `Bash(python3 -c ' *)` | из ожидания 13.08 |
| `Bash(python3 -)` | из ожидания 15.08 |

Обе означают **выполнение любого кода на Питоне** — то есть почти всё, что
можно сделать на этом компьютере. Копия прежнего списка лежит в «Резервные
копии/Список разрешений — до очистки 2026-08-15.json».

💡 **Отсюда правило: «разрешить» в ответ на застрявшую задачу — не решение,
а плата.** Оно снимает сегодняшнюю заминку и оставляет постоянную дыру,
о которой через неделю никто не помнит. И наоборот: **после очистки списка
задача не «стала ломаться» — она перестала прятать поломку за выданными
правами.** 16.08 повисло ровно то, что 13.08 тихо разрешили.

Правильное лечение — не расширять список, а убрать причину сочинять команду.

⚠️ **У задач общая дверь.** Пока висит одна, следующая не стартует — и это
не про одну задачу, а про все. 16.08 задача по чаевым захватила замок в 9:01
и повисла в 9:22; финансовая в 9:02 развернулась и до завтра не проснулась.
Замок — `.claude/scheduled_tasks.lock` в папке `Обучение ИИ`, внутри номер
процесса. Одно зависание стоило трёх суток без финансовой сводки.

**Как вылечено:**

1. Обе инструкции начинаются разделом **«Что тебе разрешено — и это весь
   список»**: у чаевых одна команда, у финансов пять, плюс почта и чтение
   файлов внутри папки проекта. Прямо сказано: сочинять нельзя, править код
   нельзя, не хватило данных — написать об этом в отчёте.
2. Проверка двойников убрана совсем. Скрипт и так печатает всех, кого нет
   в кассе, и **нарочно** отказывается гадать по похожести имён: «Лиза Н.»
   и «Елизавета Недорезова» — один человек, а общих букв в имени нет.
3. Заработок за вчера печатает сам сборщик — добывать нечего.
4. Отдельно оговорено: **строки из вывода скрипта обращены к владельцу,
   а не к задаче.** 14.08 задача прочла «впишите решение в словарь СКЛЕЙКА»
   как задание себе и полезла в код.
5. Оговорено и обратное: **фоновая команда — не новая команда.** Иначе запрет
   «не сочинять» мешал бы дождаться `fin_daily.py`, которая идёт 2–5 минут.

Инструкции: `~/.claude/scheduled-tasks/otchyot-chaevykh-nevskiy/SKILL.md`
и `~/.claude/scheduled-tasks/finansy-nevskiy-9utra/SKILL.md`. Копии прежних

## ⚠️ Что ломает прежние привычки

**1. Схему базы правим в `mini-app`, а не в бэк-офисе.**
`npm run copies` копирует `schema.sql` **из приложения смены в бэк-офис**.
Правка в `manager-app/scripts/schema.sql` молча затирается при первой же
сборке — `prebuild` вызывает проверку копий.

**2. Имена сегментов адреса — латиницей.** Папка `[день]` роняет страницу
с «InvalidCharacterError» ещё до первой строчки разметки. После переименования
надо стереть `.next` — кеш помнит старое имя. Внутри кода и в параметрах
запроса (`?месяц=`) кириллица работает нормально.

**3. `cp` с двумя образцами под zsh не копирует НИЧЕГО**, если хотя бы один
образец ни с чем не совпал: оболочка отказывается запускать команду. В bash
поведение обратное, поэтому строчка выглядела рабочей. Заменено
на `scripts/bank_pickup.py`.

**4. Роботов два, и у них разная работа.**

| Робот | Регион | Что делает | Чего не может |
|---|---|---|---|
| `chaevye-reader` | Москва | копия базы по расписанию | Telegram режет РКН |
| `chaevye-reader-var` | Варшава | читает группу, отдаёт приложению | базы не видит |

Московского **не выключать** — он единственный, кто дотягивается до базы.

⚠️ **Выкладка варшавского робота через SSH НЕ РАБОТАЕТ.** Обходили загрузкой
файлов через панель: «Репозиторий» → «Загрузить данные», перетащить **файлы**
(не папку!), zip не принимается.

**5. Ветки разведены.** Работа в `work`, `main` = бой, каждая его отправка
пересобирает **приложение смены**. Вне окна 7:00–11:00 хук не пустит.

```bash
cd "/Users/user/Documents/Невский" && git add <файлы поимённо> && git commit -m "что поменяли" && git push origin work
```

⚠️ **`git push` без имени ветки не набирать.** И **`git add -A` не набирать
вслепую**: сначала `git status`, потом файлы поимённо.

💡 **Хук стережёт только кассу.** Бэк-офис и роботы — отдельные приложения,
их выкладка зал не трогает и безопасна в любое время суток.

**Устройство страницы месяца, каким его сделала владелец 16.08:**

- сверху два блока — выручка и расходы, каждый врозь по юрлицам;
- под ними деньги на **расчётных** счетах: сколько сейчас и сколько было
  на начало дня. Депозиты сюда не идут — это копилка на налоги, а не
  оборотные деньги;
- тихой строкой «в расходах: вывод собственнику … · заимствования …»;
- переключатель юрлиц — фильтрует таблицу, блоки сверху не трогает;
- **статья раскрывается на месте** (`?раскрыть=Кухня,Ежедневка`), контрагенты
  встают теми же столбцами дней. Что раскрыто — в адресе, поэтому ложится
  в закладку и отправляется ссылкой;
- **первый столбец закреплён слева, «за месяц» — справа**, прокручиваются
  только дни между ними.

```bash
cd "/Users/user/Documents/Невский" && python3 scripts/fin_push.py 2026-08
cd "/Users/user/Documents/Невский" && python3 scripts/fin_push.py --что-там
```

   в двух местах сразу: в «Фин. своде» и в словаре в коде. Признак («тот же
   московский счёт») перевесил готовый ответ. Отсюда правило дня: выписка
   отвечает «что и когда», свод — «куда отнести», и прав свод.

0л. **Проверка, которая молчит всегда, не проверяет ничего.** Написав
   сверку дня с выпиской, я прогнал её на 8 000 операций — тишина. Тишина
   могла означать и «всё сходится», и «проверка не работает». Подсунул
   заведомо неполный день — закричала. **Проверять надо и саму проверку.**

0м. **Разобранное и неиспользуемое — то же, что несуществующее.** Остаток
   на начало дня приходил в каждой выписке с мая 2024, аккуратно разбирался
   и не показывался нигде. Нашёлся только потому, что владелец спросила.
   Стоит иногда смотреть не «чего не хватает», а «что уже лежит без дела».

0н. **Повтор, который «ничего не делает», прячет починку.** Отправка
   в бэк-офис при совпадении ключа не трогала строку вовсе — и исправленная
   на Маке разметка до базы не доезжала. Защита от удвоения не должна
   превращаться в защиту от исправления.

1. **Отчёт фиксирует только выплаты В ПОЛЬЗУ сотрудника.** Питание в отчёт
   не идёт — решение владельца 08.08.2026, **вопрос закрыт, не поднимать**.

2. **Признак существования — не признак работоспособности.** Папка Google
   Диска отвечает `is_dir() == True` мгновенно и валится по таймауту
   на первой настоящей операции. Выложено ≠ работает.

3. **Боевая база с компьютера владельца недоступна** — VPN incy перехватывает
   соединения. Проверки идут на своей базе: Postgres.app, база `chaevye`,
   схема `test`.

   ⚠️ **С этого компьютера нельзя проверить снаружи ничего, что живёт за VPN.**
   Выдуманный адрес отвечает ровно то же, что настоящая база. Проверять надо
   обратное — не «закрылась ли дверь», а «работают ли те, кто ходит изнутри».

4. **Правила деления денег лежат копиями в двух приложениях.** Правишь
   `mini-app/src/lib/split.ts` — сразу `cd manager-app && npm run copies`.

5. **Различай «не вышло» и «не делали».** Первое — повод подождать, второе —
   повторить.

6. **Диагностику пиши там, где её будут читать.** Журнал в панели листают
   с конца.

## Как поднять на своём компьютере

```bash
cd "/Users/user/Documents/Невский/mini-app" && npm run dev      # смена, порт 3000
cd "/Users/user/Documents/Невский/manager-app" && npm run dev   # бэк-офис, порт 3100
```

Вход в бэк-офис на локальной базе: логин `vika`, роль владельца.

```bash
cd manager-app && npm run manager:list                       # кто заведён
cd manager-app && npm run manager:password -- vika           # выдать новый пароль
```

Пароль **восстановить нельзя** — в базе только необратимый отпечаток.

Поднять локальную базу, если погашена:

```bash
/Applications/Postgres.app/Contents/Versions/17/bin/pg_ctl -D "$HOME/Library/Application Support/Postgres/var-17" -l "$HOME/Library/Application Support/Postgres/var-17/server.log" start
```

⚠️ **Next.js не даёт поднять второй сервер разработки в той же папке.** Если
мешает чужой — он мог остаться с прошлой сессии, гасить можно спокойно.
