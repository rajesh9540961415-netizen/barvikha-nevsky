### Три правила этого раздела, которые легко нарушить

**1. Наличные заменяются, а не дописываются.** Владелец 15.08: касса
перепроверяется руками раз в 7–10 дней, и суммы при перепроверке
**исправляются**. Защита от повторов считает платёж тем же самым по дате,
статье, столбцу и сумме — исправленная сумма делает его «новым», и старая
неверная строка осталась бы рядом. Поэтому наличные за период стираются
целиком и заливаются заново, а границы берутся по календарю месяца:
удалённой строки в пачке не будет вовсе, а стереть надо.

⚠️ **Замена разрешена ТОЛЬКО наличным.** Просьбу заменить банк адрес
отвергает: выписки задним числом не переписываются, а снесённый по ошибке
период банка — потерянный учёт.

**2. Наличные всегда отстают, и это устройство, а не заминка.** Экран пишет
«наличные — только по 6 августа» красным, до таблицы. Молча смешать свежий
банк с несвежими наличными — соврать.

**3. Статью считает Питон, а не бэк-офис.** Правила разметки живут
в `scripts/fin_articles.py`; написать их заново на TypeScript значило бы
завести вторую копию на другом языке. Статья едет готовым словом, бэк-офис
показывает присланное и ничего не вычисляет.

| Когда | Что |
|---|---|

| … | тишина 45 часов 36 минут |

**предыдущий запуск ещё висел, а новый не стартует, пока не кончился старый.**
Та же картина с начала августа — отработала 4, 7, 8, 13-го, между ними стояла.

Почта при этом была здорова: в обычной переписке те же обращения отвечали
за 3–5 секунд. Разница одна — рядом человек, который жмёт «разрешить».

**Вылечено:** нужные разрешения внесены в список заранее, инструкция
переписана так, чтобы задача не лезла туда, куда ей нельзя.

⚠️ **Список разрешений вычищен.** Было 16 строк, из них три мёртвые и **две
открывали выполнение любого кода на Питоне** — то есть почти всё, что можно
сделать на этом компьютере. Стало 14, все узкие. Файл —
`/Users/user/Claude/Projects/Обучение ИИ/.claude/settings.local.json`.

💡 **Правило:** узкие разрешения не защищают, если рядом лежит одно широкое.
И: задача, читающая почту, не должна иметь права выполнять произвольный код —
письмо это данные из внешнего мира.

## ⚠️ Что изменилось и ломает прежние привычки

**1. Схему базы правим в `mini-app`, а не в бэк-офисе.**
`npm run copies` копирует `schema.sql` **из приложения смены в бэк-офис**.
Правка в `manager-app/scripts/schema.sql` молча затирается при первой же
сборке — `prebuild` вызывает проверку копий. 15.08 наступил на это дважды:
первый раз таблицы уцелели случайно, второй раз колонка пропала и адрес приёма
упал с «column does not exist».

**2. Имена сегментов адреса — латиницей.** Папка `[день]` роняет страницу
с «InvalidCharacterError» ещё до первой строчки разметки: Next.js делает
из имени сегмента идентификатор. После переименования надо стереть `.next` —
кеш помнит старое имя. Внутри кода и в параметрах запроса (`?месяц=`)
кириллица работает нормально.

**3. `cp` с двумя образцами под zsh не копирует НИЧЕГО**, если хотя бы один
образец ни с чем не совпал: оболочка отказывается запускать команду и печатает
«no matches found». В bash поведение обратное, поэтому строчка выглядела
рабочей. Из-за этого выписки лежали в «Загрузках» с 13 по 15 августа
незамеченными. Заменено на `scripts/bank_pickup.py`.

**4. Роботов два, и у них разная работа.**

| Робот | Регион | Что делает | Чего не может |
|---|---|---|---|
| `chaevye-reader` | Москва | копия базы по расписанию | Telegram режет РКН |
| `chaevye-reader-var` | Варшава | читает группу, отдаёт приложению | базы не видит |

Московского **не выключать** — он единственный, кто дотягивается до базы.

⚠️ **Выкладка варшавского робота через SSH НЕ РАБОТАЕТ.** Обходили загрузкой
файлов через панель: «Репозиторий» → «Загрузить данные», перетащить **файлы**
(не папку!), zip не принимается.

**5. Ветки разведены.** Работа в `work`, `main` = бой, каждая его отправка
пересобирает **приложение смены**. Вне окна 7:00–11:00 хук не пустит.

```bash
cd "/Users/user/Documents/Невский" && git add <файлы поимённо> && git commit -m "что поменяли" && git push origin work
```

⚠️ **`git push` без имени ветки не набирать.** И **`git add -A` не набирать
вслепую**: сначала `git status`, потом файлы поимённо.

💡 **Хук стережёт только кассу.** Бэк-офис и роботы — отдельные приложения,
их выкладка зал не трогает и безопасна в любое время суток.

## Десять вещей, без которых споткнёшься

0а. **Признак работы — не признак ПРАВИЛЬНОЙ работы.** Читатель чаевых
   подключался, находил группу с нужным именем и честно докладывал
   «поступлений нет» — а три дня читал не ту группу. **Имя — не удостоверение
   личности.** Проверять надо не «жив ли», а «то ли он делает».

0б. **У каждой суммы на новом экране должен быть эталон, посчитанный другим
   путём.** 15.08 в разделе финансов нашлись три ошибки — вычтенные дважды
   возвраты, потерянная комиссия эквайринга, отметка «заполнено по», ходившая
   назад. **Ни одна не видна по самому экрану**: 10 671 685 вместо 10 671 899
   глазами не поймать. Все три нашлись сверкой.

0в. **Закладывай запасной путь, который вылезает наружу, а не прячет.**
   Статья не из списка порядка — показывается отдельной строкой, а не молча
   пропадает. Незнакомое юрлицо — отдельной группой, а не сливается с соседями.
   15.08 именно так нашлась потерянная привязка эквайринга: некрасиво
   на экране, зато сразу видно.

0г. **Сомнительное значение не показывать вовсе.** 13.08 Node напечатал
   в журнал строку целиком, вместе с паролем от базы. **Секрет утекает не там,
   где вы его печатаете, а там, где о нём споткнулась чужая библиотека.**

0д. **Кириллица в именах переменных оболочки — молчаливая ложь.** zsh
   не понимает такие присваивания: команда падает, а выглядит выполненной.
   15.08 это стоило утечки ключа — оболочка напечатала присваивание целиком
   вместе со значением. **Имена переменных только латиницей**, а секреты вообще
   не гонять через переменные оболочки: пусть их читает та программа, которой
   они нужны.

0е. **Два чата в одной папке — грабли, а не мелочь.** 14.08 один чат забрал
   в свой коммит чужую незаконченную работу. **Один чат на папку за раз.**

1. **Отчёт фиксирует только выплаты В ПОЛЬЗУ сотрудника.** Питание в отчёт
   не идёт — решение владельца 08.08.2026, **вопрос закрыт, не поднимать**.

2. **Признак существования — не признак работоспособности.** Папка Google
   Диска отвечает `is_dir() == True` мгновенно и валится по таймауту
   на первой настоящей операции. Выложено ≠ работает.

3. **Боевая база с компьютера владельца недоступна** — VPN incy перехватывает
   соединения. Проверки идут на своей базе: Postgres.app, база `chaevye`,
   схема `test`.

   ⚠️ **С этого компьютера нельзя проверить снаружи ничего, что живёт за VPN.**
   Выдуманный адрес отвечает ровно то же, что настоящая база. Проверять надо
   обратное — не «закрылась ли дверь», а «работают ли те, кто ходит изнутри».

4. **Правила деления денег лежат копиями в двух приложениях.** Правишь
   `mini-app/src/lib/split.ts` — сразу `cd manager-app && npm run copies`.

5. **Различай «не вышло» и «не делали».** Первое — повод подождать, второе —
   повторить.

6. **Диагностику пиши там, где её будут читать.** Журнал в панели листают
   с конца.

## Как поднять на своём компьютере

```bash
cd "/Users/user/Documents/Невский/mini-app" && npm run dev      # смена, порт 3000
cd "/Users/user/Documents/Невский/manager-app" && npm run dev   # бэк-офис, порт 3100
```

Вход в бэк-офис на локальной базе: логин `vika`, роль владельца.

```bash
cd manager-app && npm run manager:list                       # кто заведён
cd manager-app && npm run manager:password -- vika           # выдать новый пароль
```

Пароль **восстановить нельзя** — в базе только необратимый отпечаток.

Поднять локальную базу, если погашена:

```bash
/Applications/Postgres.app/Contents/Versions/17/bin/pg_ctl -D "$HOME/Library/Application Support/Postgres/var-17" -l "$HOME/Library/Application Support/Postgres/var-17/server.log" start
```

⚠️ **Next.js не даёт поднять второй сервер разработки в той же папке.** Если
мешает чужой — он мог остаться с прошлой сессии, гасить можно спокойно.
