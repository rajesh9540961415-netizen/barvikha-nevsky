# Читатель QR-чаевых

Отдельное приложение. Раз в минуту заглядывает в группу Telegram «Сберчаевые Нев», разбирает уведомления «СберЧаевые PRO» и кладёт новые поступления в таблицу `qr_tips`. Оттуда их подхватывает приложение смены и показывает кассиру полосой «Чаевые по QR».

**Почему отдельно от приложения смены.** Сбой чтения Telegram не должен мешать вносить деньги в зале. И наоборот: выкладка читателя не кладёт приложение, которым в этот момент пользуется смена.

## Что где лежит

| Файл | Зачем |
|---|---|
| `service.py` | сама служба: заход раз в минуту, тревога о молчании, отметка «жив» раз в час |
| `qr_reader.py` | общее ядро — расчёт смены, чтение группы, запись в базу. **Тот же код** запускается и вручную скриптом `../scripts/tg_read.py` |
| `sber_parse.py` | разбор одного уведомления. Запускается сам собой и проверяет себя: `python3 sber_parse.py` |
| `storage.py` | куда складывать прочитанное: прямо в базу или через приложение по https |
| `jobs.py` | расписание: что делать по времени и как не сделать дважды |
| `bar_reader.py` | состав и мотивация кальянного бара из «НЕВСКИЙ \| ОБЩИЙ ЧАТ» и «НЕВСКИЙ \| АДМИН», с 20.10.2026 |
| `bar_parse.py` | разбор «РАСПРЕДЕЛЕНИЯ» и отчёта о мотивации. Проверяет себя: `python3 bar_parse.py` |
| `backup.py` | резервная копия базы — архив под паролем в Telegram |
| `Dockerfile`, `amvera.yaml` | сборка для Amvera |

Ядро общее намеренно: две копии расчёта смены рано или поздно разъедутся, и суммы поедут вслед за ними.

## Расписание

С 11.08.2026 читатель — не только читатель. Кроме чтения Telegram раз в минуту у него есть дела по времени.

| Дело | Когда | Что делает |
|---|---|---|
| копия базы | понедельник, 5 утра | выгружает все таблицы, кладёт в архив под паролем и отправляет в «Избранное» служебного аккаунта Telegram |

**Почему расписание здесь, а не в приложении Claude на компьютере.** Задачи Claude идут, только пока это приложение открыто: 10 и 11 августа 2026 задача по финансам не сработала вовсе. Сервер работает всегда.

**Пропуск не страшен.** Простоял робот весь понедельник — через восемь дней он возьмётся за дело не дожидаясь следующего понедельника. Отметка о сделанном лежит в базе, в таблице `robot_jobs`, а не в памяти: контейнер перезапускается при каждой выкладке.

⚠️ Таблицы `robot_jobs` нет в `schema.sql` приложения смены намеренно — это собственность робота, в неё никто больше не смотрит. Робот заводит её сам при старте.

## Что задать в панели Amvera

Переменные окружения, вкладка «Переменные», этап **«Запуск»**:

| Имя | Значение |
|---|---|
| `DATABASE_URL` | та же строка, что у приложения смены — **внутренний** адрес базы, `amvera-borzovavv-cnpg-chaevye1-rw` |
| `TG_API_ID` | из `.env` проекта |
| `TG_API_HASH` | из `.env` проекта |
| `TG_GROUP_ID` | `-1003807015954` — группа «Сберчаевые Нев». ⚠️ Не переписывать по памяти, см. ниже |
| `TG_SESSION` | сессия строкой, см. ниже |
| `QR_SINCE_DAY` | с какой смены начинать при первом запуске, например `2026-08-05` |
| `BACKUP_PASSWORD` | пароль от архива с копией базы, см. ниже |
| `TG_BOT_TOKEN` | ключ бота из @BotFather — им робот **отправляет** копию базы |
| `TG_BACKUP_CHAT` | переписка, куда слать копию. Не задана — робот подскажет число в журнале |
| `TG_CONNECTION` | способ подключения к Telegram, если обычный не работает: `full`, `abridged`, `obfuscated`, `http`. Не задан — робот перебирает их сам и пишет в журнал, какой подошёл |

⚠️ **Номер группы не переписывать по памяти и не брать из старых записей.**
Групп с именем «Сберчаевые Нев» две, и живая только одна.

| Номер | Что это |
|---|---|
| `-1003807015954` | **живая**, супергруппа. Сбер шлёт сюда |
| `-5484146873` | мёртвая, прежняя. Последнее поступление 04.08.2026 в 14:24 |

Так вышло 04.08.2026: группу преобразовали в супергруппу, а Телеграм при этом
не переименовывает старую, а заводит рядом новую. Имя то же, номер другой,
нумерация сообщений начата заново с единицы. Старая никуда не девается
и выглядит исправной — в ней просто больше ничего не появляется.

**Перед тем как вписать номер, сверьте его с содержимым, а не с именем:**

```bash
python3 scripts/tg_groups.py                              # какие группы есть
TG_GROUP_ID=<номер> python3 scripts/tg_read.py            # что в ней лежит
```

Живая группа покажет поступления за последние дни, мёртвая — тишину.
Ошибка стоила десяти суток потерянных чаевых в августе 2026: робот
подключался, находил группу с нужным именем и честно докладывал «поступлений
нет». Разбор — `plans/2026-08-10-sverka-s-sberom.md`.

⚠️ **Читает и отправляет робот разными путями, и это не прихоть.** Чтение группы
идёт по MTProto (`telethon`), отправка копии — обычным https через
`api.telegram.org` (`tgbot.py`). С Amvera 11.08.2026 работает только второе.
Ботом читать группу нельзя: Telegram не даёт ботам видеть сообщения других
ботов, а уведомления шлёт бот «СберЧаевые PRO» — проверено владельцем.

`DATABASE_SCHEMA` **не задавать** — тогда читатель пишет в боевую схему `public`, как и приложение.

### Пароль от копии базы

В базе фамилии сотрудников и все их заработки, а «Избранное» Telegram — чужое облако. Поэтому архив шифруется, и **без `BACKUP_PASSWORD` копия не делается вовсе**: робот скажет об этом в журнале при каждом старте. Молча сложить открытые фамилии в чужое облако хуже, чем не сложить ничего.

Пароль надо хранить у себя — без него архив не открыть никому, включая владельца.

⚠️ **Архив зашифрован по-настоящему (AES), и встроенный распаковщик macOS его не открывает** — двойной щелчок скажет «ошибка 79» или просто ничего не сделает. Это не поломка, а цена настоящего шифрования: старый формат, который macOS понимает, вскрывается за секунды. Открыть можно бесплатной программой Keka или командой на компьютере:

```bash
python3 -c "import pyzipper,sys; z=pyzipper.AESZipFile(sys.argv[1]); z.setpassword(sys.argv[2].encode()); z.extractall(sys.argv[3])" ~/Downloads/база-невский-ГГГГ-ММ-ДД.zip 'пароль' ~/Downloads/копия
```

⚠️ Переменные читаются только при старте. После правки контейнер нужно перезапустить.

### Сессия строкой

Файл сессии на диске — лишняя дыра: его легко скопировать вместе с кодом и легко забыть. Поэтому сессия едет переменной окружения.

На компьютере владельца:

```bash
python3 "/Users/user/Documents/Невский/scripts/tg_session_export.py"
```

Строка ляжет в файл `scripts/.tg-session-string.txt` — на экран она не печатается. Скопировать её в переменную `TG_SESSION` в панели Amvera, **после чего файл удалить**.

⚠️ Эта строка — ключ от аккаунта Telegram, не хуже пароля. Не пересылать в мессенджерах, не вставлять в переписку.

## Два робота: Москва и Варшава *(с 13.08.2026)*

РКН периодически режет из России соединения к дата-центрам Telegram —
подтверждено поддержкой Amvera 13.08.2026. Московский читатель из-за этого
не прочитал ни одного поступления с 4 августа. В Варшаве Telegram отвечает
первым же способом.

Но **внутреннее имя базы разрешается только внутри своего региона** — из
Варшавы московская база не видна вовсе. Amvera предложила два выхода, и оба
не годятся: открыть базу в интернет нельзя (в ней фамилии и заработки
17 человек), перенести базу в Варшаву нельзя по 152-ФЗ.

Поэтому сделан третий: **варшавский робот отдаёт прочитанное приложению смены
по обычному https, а в базу пишет приложение.** Адрес `/api/qr-tips`, ключ
тот же `EXPORT_KEY`.

💡 Побочная выгода важнее удобства: через границу едет только сумма, котёл
(«Официант 2») и время. **Персональных данных в этом потоке нет вовсе** —
а при прямом доступе к базе за рубежом оказалась бы вся она.

| Робот | Регион | Что делает |
|---|---|---|
| `chaevye-reader` | Москва | копия базы по расписанию. Telegram ему недоступен |
| `chaevye-reader var` | Варшава | читает группу и отдаёт приложению. Базы у него нет |

Московского **не выключать**: он единственный, кто дотягивается до базы,
а копия базы без неё невозможна.

Переменные варшавского, сверх обычных:

| Имя | Значение |
|---|---|
| `CHAEVYE_API` | `https://smena.barvikha-nevsky.ru` — включает передачу по https |
| `CHAEVYE_EXPORT_KEY` | то же значение, что `EXPORT_KEY` у приложения `chaevye` |

⚠️ **Ключ только латиницей.** Он едет в заголовке HTTP, а там кириллица
не ездит: приложение получит искажённое значение и ответит «неверный ключ».
Наступили на это 13.08.2026 при проверке.

## Кальянный бар: состав и мотивация *(с 20.10.2026)*

Раз в 15 минут варшавский робот перечитывает за последние три дня две группы
и отдаёт приложению на `/api/bar-chat` (тот же ключ, что у QR):

| Группа | Что ищет |
|---|---|
| «НЕВСКИЙ \| ОБЩИЙ ЧАТ» | «РАСПРЕДЕЛЕНИЕ ДД.ММ.ГГ» → раздел «КАЛЬЯННЫЙ БАР» и строка «КМ» |
| «НЕВСКИЙ \| АДМИН» | «Мотивация кальянного бара» → штуки по типам и итог |

⚠️ **Здесь через границу едут имена** — решение владельца 20.10.2026. Только
раздел бара, не всё распределение; в журнал имена не пишутся. Опознаёт их
приложение по своему справочнику бара.

Видит ли робот обе группы, он проверяет сам при каждом подключении: в журнале
строка `бар: группа … видна` или `⚠️ бар: группа … НЕ видна`, а в базе — таблица
`tg_sources`, которую видно дверью бэк-офиса `/api/bar-chat`. Раньше обе группы
читали с Мака под другим аккаунтом — служебного аккаунта робота там может не быть.

Переменные, все необязательные:

| Имя | Значение |
|---|---|
| `TG_ADMIN_GROUP_ID` | «НЕВСКИЙ \| АДМИН», по умолчанию `-1002111693197` |
| `TG_CREW_GROUP_ID` | «НЕВСКИЙ \| ОБЩИЙ ЧАТ»; не задан — ищется по названию, при двойниках берётся самый свежий |
| `BAR_SINCE_DAY` | с какой смены читать, пока в базе пусто; не задан — 30 дней назад |

Московскому роботу (прямо с базой) бар не поручается: Telegram из Москвы
не читается, а опознание имён живёт в приложении.

План: `plans/2026-10-20-bar-iz-telegram.md`.

## Если робот не подключается к Telegram

Случилось 11.08.2026: шесть попыток подряд упирались в тишину, робот падал,
Amvera перезапускала его, и журнал забивался одинаковыми падениями.

Теперь при неудаче робот **остаётся жив** и раз в минуту пробует снова,
а в журнал один раз пишет проверку связи — куда он с этого сервера
дозванивается, а куда нет, и что это значит. Читать её сверху вниз,
последняя строка «итог: …» и есть вывод.

Заодно он перебирает четыре способа подключения: обычный ходит по порту 443,
запасной — через 80, который открыт почти везде. Подошёл не обычный — робот
скажет, какую переменную вписать, чтобы больше не перебирать.

⚠️ **С компьютера владельца эту проверку запускать бесполезно** — VPN incy
принимает любое соединение, и она показывает сплошные «✓». Проверка знает
об этом сама: стучится в заведомо несуществующий адрес и, если тот «ответил»,
честно отказывается делать выводы.

## Как выложить

Читатель лежит в подпапке общего репозитория, а Amvera собирает из корня. Поэтому отправляем не весь репозиторий, а только эту папку — она станет корнем:

```bash
cd "/Users/user/Documents/Невский" && git subtree push --prefix tg-reader amvera-reader master
```

Один раз перед этим надо завести адрес, который выдаст панель Amvera при создании приложения:

```bash
cd "/Users/user/Documents/Невский" && git remote add amvera-reader ssh://git@git.amvera.ru:2022/borzovavv/<имя-приложения>
```

**Выкладка читателя безопасна в любое время** — приложение смены она не трогает.

## Как проверить, что работает

В журнале приложения в панели Amvera должно быть:

```
читаю группу «Сберчаевые Нев» раз в 60 с
жив. Последнее поступление: 04.08 в 14:24 (0.4 ч назад) — рассылка жива.
```

Когда приходят чаевые:

```
записано 1 на 460.00 ₽ (схема public, пропущено чужих 2, старых 0)
  2026-08-05 23:41 — 460.00 ₽ · Официант 5
```

Когда рассылка молчит дольше суток — раз в час:

```
⚠️  Последнее поступление было 26.07 в 03:56 — это 9.2 суток назад.
```

## Проверить руками, не выкладывая

Один заход и выход:

```bash
cd "/Users/user/Documents/Невский/tg-reader" && python3 service.py --once
```

Понадобятся те же переменные окружения. На компьютере владельца проще пользоваться `../scripts/tg_read.py` — он берёт их из файлов проекта сам и по умолчанию пишет в тестовую схему.
