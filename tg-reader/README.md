# Читатель QR-чаевых

Отдельное приложение. Раз в минуту заглядывает в группу Telegram «Сберчаевые Нев», разбирает уведомления «СберЧаевые PRO» и кладёт новые поступления в таблицу `qr_tips`. Оттуда их подхватывает приложение смены и показывает кассиру полосой «Чаевые по QR».

**Почему отдельно от приложения смены.** Сбой чтения Telegram не должен мешать вносить деньги в зале. И наоборот: выкладка читателя не кладёт приложение, которым в этот момент пользуется смена.

## Что где лежит

| Файл | Зачем |
|---|---|
| `service.py` | сама служба: заход раз в минуту, тревога о молчании, отметка «жив» раз в час |
| `qr_reader.py` | общее ядро — расчёт смены, чтение группы, запись в базу. **Тот же код** запускается и вручную скриптом `../scripts/tg_read.py` |
| `sber_parse.py` | разбор одного уведомления. Запускается сам собой и проверяет себя: `python3 sber_parse.py` |
| `jobs.py` | расписание: что делать по времени и как не сделать дважды |
| `backup.py` | резервная копия базы — архив под паролем в Telegram |
| `Dockerfile`, `amvera.yaml` | сборка для Amvera |

Ядро общее намеренно: две копии расчёта смены рано или поздно разъедутся, и суммы поедут вслед за ними.

## Расписание

С 11.08.2026 читатель — не только читатель. Кроме чтения Telegram раз в минуту у него есть дела по времени.

| Дело | Когда | Что делает |
|---|---|---|
| копия базы | понедельник, 5 утра | выгружает все таблицы, кладёт в архив под паролем и отправляет в «Избранное» служебного аккаунта Telegram |

**Почему расписание здесь, а не в приложении Claude на компьютере.** Задачи Claude идут, только пока это приложение открыто: 10 и 11 августа 2026 задача по финансам не сработала вовсе. Сервер работает всегда.

**Пропуск не страшен.** Простоял робот весь понедельник — через восемь дней он возьмётся за дело не дожидаясь следующего понедельника. Отметка о сделанном лежит в базе, в таблице `robot_jobs`, а не в памяти: контейнер перезапускается при каждой выкладке.

⚠️ Таблицы `robot_jobs` нет в `schema.sql` приложения смены намеренно — это собственность робота, в неё никто больше не смотрит. Робот заводит её сам при старте.

## Что задать в панели Amvera

Переменные окружения, вкладка «Переменные», этап **«Запуск»**:

| Имя | Значение |
|---|---|
| `DATABASE_URL` | та же строка, что у приложения смены — **внутренний** адрес базы, `amvera-borzovavv-cnpg-chaevye1-rw` |
| `TG_API_ID` | из `.env` проекта |
| `TG_API_HASH` | из `.env` проекта |
| `TG_GROUP_ID` | `-5484146873` — группа «Сберчаевые Нев» |
| `TG_SESSION` | сессия строкой, см. ниже |
| `QR_SINCE_DAY` | с какой смены начинать при первом запуске, например `2026-08-05` |
| `BACKUP_PASSWORD` | пароль от архива с копией базы, см. ниже |

`DATABASE_SCHEMA` **не задавать** — тогда читатель пишет в боевую схему `public`, как и приложение.

### Пароль от копии базы

В базе фамилии сотрудников и все их заработки, а «Избранное» Telegram — чужое облако. Поэтому архив шифруется, и **без `BACKUP_PASSWORD` копия не делается вовсе**: робот скажет об этом в журнале при каждом старте. Молча сложить открытые фамилии в чужое облако хуже, чем не сложить ничего.

Пароль надо хранить у себя — без него архив не открыть никому, включая владельца.

⚠️ **Архив зашифрован по-настоящему (AES), и встроенный распаковщик macOS его не открывает** — двойной щелчок скажет «ошибка 79» или просто ничего не сделает. Это не поломка, а цена настоящего шифрования: старый формат, который macOS понимает, вскрывается за секунды. Открыть можно бесплатной программой Keka или командой на компьютере:

```bash
python3 -c "import pyzipper,sys; z=pyzipper.AESZipFile(sys.argv[1]); z.setpassword(sys.argv[2].encode()); z.extractall(sys.argv[3])" ~/Downloads/база-невский-ГГГГ-ММ-ДД.zip 'пароль' ~/Downloads/копия
```

⚠️ Переменные читаются только при старте. После правки контейнер нужно перезапустить.

### Сессия строкой

Файл сессии на диске — лишняя дыра: его легко скопировать вместе с кодом и легко забыть. Поэтому сессия едет переменной окружения.

На компьютере владельца:

```bash
python3 "/Users/user/Documents/Невский/scripts/tg_session_export.py"
```

Строка ляжет в файл `scripts/.tg-session-string.txt` — на экран она не печатается. Скопировать её в переменную `TG_SESSION` в панели Amvera, **после чего файл удалить**.

⚠️ Эта строка — ключ от аккаунта Telegram, не хуже пароля. Не пересылать в мессенджерах, не вставлять в переписку.

## Как выложить

Читатель лежит в подпапке общего репозитория, а Amvera собирает из корня. Поэтому отправляем не весь репозиторий, а только эту папку — она станет корнем:

```bash
cd "/Users/user/Documents/Невский" && git subtree push --prefix tg-reader amvera-reader master
```

Один раз перед этим надо завести адрес, который выдаст панель Amvera при создании приложения:

```bash
cd "/Users/user/Documents/Невский" && git remote add amvera-reader ssh://git@git.amvera.ru:2022/borzovavv/<имя-приложения>
```

**Выкладка читателя безопасна в любое время** — приложение смены она не трогает.

## Как проверить, что работает

В журнале приложения в панели Amvera должно быть:

```
читаю группу «Сберчаевые Нев» раз в 60 с
жив. Последнее поступление: 04.08 в 14:24 (0.4 ч назад) — рассылка жива.
```

Когда приходят чаевые:

```
записано 1 на 460.00 ₽ (схема public, пропущено чужих 2, старых 0)
  2026-08-05 23:41 — 460.00 ₽ · Официант 5
```

Когда рассылка молчит дольше суток — раз в час:

```
⚠️  Последнее поступление было 26.07 в 03:56 — это 9.2 суток назад.
```

## Проверить руками, не выкладывая

Один заход и выход:

```bash
cd "/Users/user/Documents/Невский/tg-reader" && python3 service.py --once
```

Понадобятся те же переменные окружения. На компьютере владельца проще пользоваться `../scripts/tg_read.py` — он берёт их из файлов проекта сам и по умолчанию пишет в тестовую схему.
